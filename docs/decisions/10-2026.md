## Bind each CLI command's dependencies at composition and preserve terminal lifecycle behavior

- **Date:** 2026-10-02
- **Decided by:** GPT-6 Astra, implementing the maintainer's approved CLI SOLID refactor
- **Context:** review of the delegated extraction found a shared dependency bag, duplicated helpers and changes to masking, AI remedy text and server shutdown.
- **Decision:** compose a map of bound command handlers, each receiving its own service contract. Keep exit-code assignment separate from termination after server close; preserve help/version and asynchronous listen-error exit behavior. Regression coverage exercises failure redaction, report masking, AI remedies, unknown command names, and server close/listen-error behavior. CLI tests and fixtures live under `app/tests/features/cli/`, while existing test roots remain discoverable.

## Server MVC: thin controllers, narrow orchestrations, composition in app.ts

- **Date:** 2026-10-02
- **Decided by:** MiniMax M3, with the maintainer's staged server refactor brief
- **Context:** the CLI was refactored to SOLID command boundaries; the server is the next scope. Controllers (`/api/plan`, `/api/runs/*`, `/api/rerun`, `/api/ai`, `/api/accounts`) still imported `engine/redact`, `engine/errors`, `server/accounts` helpers and `services.*` re-exports inline, mixing orchestration with parsing. The `Services` facade re-exported everything controllers might need (`startRun`, `runState`, `listRuns`, `diskSummary`, `isUserError`, `redactSecrets`, `cleanErrorMessage`, `planWarnings`, `checkTitles`), turning it into a god object.
- **Decision:** keep `Services` as the composition-root / dependency-injection seam and shrink it to the slice controllers actually use (`host`, `plans`, `runs`, `signInTests`, `canShowBrowser`, `version`, `options`, `startRun`, `discoverAndPlan`, `runState`, `listRuns`, `isRedactedPlan`). Move the orchestration into per-feature modules: `server/models/plan-flow.ts` (`planForRequest`, `redactPlan`, `flowError`, `isUserError`, `isRedactedTarget`), `server/models/run-flow.ts` (`rerunPlanFor`, `countRunning`, `concurrentRunsMessage`), `server/models/account-flow.ts` (`readyAccount`, `isAccountId`), `server/models/redact-text.ts` (`neutralRedactor`, `redactorFor`), `server/models/ai-models.ts` (`resolveModelsList`). Controllers parse the request, call the orchestration, format the response. UI is unchanged.
- **Why:** each orchestration owns one responsibility (planning, re-planning, account readiness, redaction, model-list) and is testable without a Hono app; controllers shrink to parse-and-format. The `Services` interface stops being a re-export bag and becomes a real DI seam.
- **Consequences:** byte-for-byte behaviour preserved — routes, status codes, headers, JSON shapes, error messages, password registration/unregistration, isRedactedPlan order, concurrent-runs guard, account-readiness checks. New boundary tests in `app/tests/features/server/flow-boundaries.test.ts` (39 tests) cover the orchestrations in isolation. All 3024 app tests pass; `lint` clean for the touched files. The unchanged pre-existing lint findings across tests stay to be resolved in follow-up.
- **Sources:** `app/src/server/controllers/plan-controller.ts`, `app/src/server/controllers/runs-controller.ts`, `app/src/server/controllers/accounts-controller.ts`, `app/src/server/controllers/ai-controller.ts`, `app/src/server/models/plan-flow.ts`, `app/src/server/models/run-flow.ts`, `app/src/server/models/account-flow.ts`, `app/src/server/models/redact-text.ts`, `app/src/server/models/ai-models.ts`, `app/src/server/models/services.ts`, `app/tests/features/server/flow-boundaries.test.ts`.

<a id="2026-10-02-server-narrow-ports"></a>
## Server: replace Services bag with per-controller flow ports

- **Date:** 2026-10-02
- **Decided by:** MiniMax M3, completing the server SOLID refactor
- **Context:** the previous entry shrank `Services` to a smaller re-export bag, but every controller still reached into a single object for many unrelated concerns. The plan, runs, accounts, AI and UI controllers each had different needs; sharing a `Services` object was still a god-facade. `app/src/server/interfaces/server.ts` (duplicate of the canonical `app/src/interfaces/server.ts`) and `app/src/server/types/server.ts` (just a re-export shim) were leftovers from before the canonical-homes decision.
- **Decision:** introduce one narrow port per controller in `app/src/interfaces/server.ts` — `IPlanFlow`, `IRunsFlow`, `IAccountsFlow`, `IAiFlow`, `IUiFlow`. Each port exposes only what its controller consumes; each port's input/output types are co-located with the controller contract (not duplicated in model files). Build the implementations as `PlanFlow`, `RunsFlow`, `AccountsFlow`, `AiFlow`, `UiFlow` classes in `server/models/`, each taking its own narrow `*Deps` via the constructor. Composition root `server/app.ts` instantiates the models, then the flows with their deps, then registers controllers with `{ flow }`. The duplicated `app/src/server/interfaces/server.ts` and the re-export `app/src/server/types/server.ts` are removed; `REDACTED` and the state types live in `app/src/types/server.ts`.
- **Why:** each controller depends on one narrow interface; the flow's process.env and engine reads live behind its constructor; the composition root is the only place that knows the concrete model objects. Flow input/output types live next to the port contract, not inline in the model, so the model can be read without parsing a types-file preamble.
- **Consequences:** the original `Services` interface is removed; controllers no longer import `Services`. Behaviour preserved byte-for-byte (the app-accounts-wiring test still passes its 6 expect-calls checks, including plan-then-run sign-in/unregister symmetry; the runs-controller's order is restored — unknown plan 404 before approved-shape 400 — via the RunsFlow.start order). All 3025 app tests pass. The flow-boundaries test now uses `PlanFlow`/`RunsFlow`/`AccountsFlow` directly and asserts the unregister hook is callable on every outcome, plus regression tests for redaction of `notReadyMessage` (configured label can be a secret) and of the plan flow's account-refusal path. Lint clean for all touched files.
- **Sources:** `app/src/server/controllers/plan-controller.ts`, `app/src/server/controllers/runs-controller.ts`, `app/src/server/controllers/accounts-controller.ts`, `app/src/server/controllers/ai-controller.ts`, `app/src/server/controllers/ui-controller.ts`, `app/src/server/app.ts`, `app/src/server/models/plan-flow.ts`, `app/src/server/models/run-flow.ts`, `app/src/server/models/account-flow.ts`, `app/src/server/models/ai-flow.ts`, `app/src/server/models/ui-flow.ts`, `app/src/server/models/services.ts`, `app/src/interfaces/server.ts`, `app/src/types/server.ts`, `app/tests/features/server/flow-boundaries.test.ts`.
