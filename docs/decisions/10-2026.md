<a id="2026-10-01-cli-solid-refactor"></a>
## Refactor the CLI around command responsibilities and explicit dependencies before server MVC

- **Date:** 2026-10-01
- **Decided by:** Rahul Bharati (maintainer), with CLI decomposition planned by GPT-6 Astra
- **Context:** the maintainer requested SOLID principles for the app, MVC for the server, and selected the CLI as the next scope. Tests should live in a tests folder grouped by feature, utility and configuration.
- **Decision:** keep `app/src/cli.ts` as the executable entrypoint; separate dispatch, command handlers, presentation and I/O, with explicit command dependencies wired at startup. Keep CLI declarations in feature-named interfaces/types modules and option configuration in `config/cli.ts`. Move CLI tests to `app/tests/features/cli/`, retaining discovery of other tests during the staged migration.
- **Why:** give CLI responsibilities independent boundaries while preserving its observable behavior and enabling focused testing.
- **Consequences:** preserve command syntax, output, exit codes, redaction, password input and server lifecycle behavior. Server MVC and migration of other features' tests are deferred. Validate the combined accounts/CLI changes after active work finishes.
- **Sources:** maintainer instructions and CLI decomposition in this session; `app/src/cli.ts`.

<a id="2026-10-02-cli-command-boundaries"></a>
## Bind each CLI command's dependencies at composition and preserve terminal lifecycle behavior

- **Date:** 2026-10-02
- **Decided by:** GPT-6 Astra, implementing the maintainer's approved CLI SOLID refactor
- **Context:** review of the delegated extraction found a shared dependency bag, duplicated helpers and changes to masking, AI remedy text and server shutdown.
- **Decision:** compose a map of bound command handlers, each receiving its own service contract. Keep exit-code assignment separate from termination after server close; preserve help/version and asynchronous listen-error exit behavior. Reuse the existing closed-pipe helper, infer argument types from option descriptors, and centralize CLI test declarations by feature.
- **Why:** enforce the requested responsibility and dependency boundaries without changing the CLI contract.
- **Consequences:** commands no longer depend on a shared service registry or global process I/O. Regression coverage exercises failure redaction, report masking, AI remedies, unknown command names, and server close/listen-error behavior. CLI tests and fixtures live under `app/tests/features/cli/`, while existing test roots remain discoverable.
- **Sources:** `app/src/cli/compose.ts`, `app/src/cli/dispatch.ts`, `app/src/interfaces/cli.ts`, `app/src/types/cli.ts`, `app/tests/features/cli/`.

<a id="2026-10-02-app-oxlint"></a>
## Use Oxlint as the app's lint runner

- **Date:** 2026-10-02
- **Decided by:** GPT-6 Astra, fulfilling the maintainer's lint request
- **Context:** the app had no linter; the maintainer asked to add one and check for issues. `typescript-eslint` does not support TypeScript 7, the app's compiler version.
- **Decision:** add Oxlint 1.86.0 to the app with a minimal `.oxlintrc.json` (correctness category), expose `lint`, `lint:fix`, and a CLI-scoped `lint:cli` script. Keep `tsc --noEmit` as the typecheck.
- **Why:** Oxlint is fast, supports the project's Node engine, and covers the syntax-based findings without a TypeScript downgrade. Splitting a CLI-scoped lint keeps refactor feedback scoped to current work.
- **Consequences:** `lint:cli` is clean. The full `lint` reports 340 findings outside the CLI scope (mostly unused imports across existing tests). Resolve those in follow-up work; refactoring stays scoped to one feature at a time.
- **Sources:** `app/.oxlintrc.json`, `app/package.json`, Oxlint 1.86.0 docs.
